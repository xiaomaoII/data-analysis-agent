# 五分钟演示与个人复现

## 演示顺序

1. 用半分钟说明：这是有限业务域的 AI Analyst；真实数据与合成数据、模型调用与固定演示分别标识。
2. 选择真实开发期数据，展示可用日期和“送礼覆盖率”的用户日分母。
3. 提交预设问题，展示整体查询与年龄／性别原始码下钻。
4. 展示一个数值，打开对应 SQL、证据编号和数据版本，说明可以复算。
5. 提交“最近付费率为什么下降？”展示澄清；提交“比较最近七天和前七天的礼物价值”展示窗口不够时不会截短冒充完整比较。
6. 说明数据不支持收入、因果原因和长期 LTV；真实模型未配置时不能宣称其准确率或自主分析效果。

若要演示“未下降”的合成情景，可在停止服务后于独立演示目录准备 increase 情景，再运行内置“礼物价值一定下降了，证明下降原因”。测试中也固定验证此分支。请不要把该情景包装成真实业务发现。

## 分模块学习

下表初始全部为“本人待复现”；Agent 实现和测试通过不表示本人独立掌握。

| 顺序 | 本人任务 | 验收证据 |
|---|---|---|
| 1 | 启动页面，解释两种数据与两种模式 | 本人操作和口头解释 |
| 2 | 解释为什么不能平均每日送礼覆盖率 | 用两个不同分母的日期手算 |
| 3 | 先说明 user_daily、daily_metrics、daily_segment_metrics 各自一行代表什么，再对照前两表复算一个指标 | 本人粒度／唯一键说明、SQL 与结果；能说明何时允许再次聚合 |
| 4 | 找一条错误日期或分母 SQL，解释为什么拒绝；查看一份校验记录，解释一项失败如何影响指标 | 本人分析及测试输出；能区分缺失值、零行为和 JOIN 重复计算 |
| 5 | 复算一个分组贡献并还原整体差值 | 本人计算和口径说明 |
| 6 | 解释 LangGraph 各步骤，触发一次澄清和一次失败 | 本人讲述与操作 |
| 7 | 修改一个指标定义或新增一个经过核验的指标 | 本人改动、测试与限制说明 |
| 8 | 配置真实模型后分析一条新问题，人工核验报告 | 输入、真实输出、本人核验及修订 |

建议记录本人尝试、参考内容、修改、运行证据和仍不理解的问题，分别标记 independent / prompted / reference。不要修改项目二的学习状态。

第 3、4 步查阅[表粒度与基础校验](architecture.md#表粒度与使用规则)。机械检查由程序执行，本人重点验收口径、预期和失败解释；不要求重写全部校验代码。仍按上表八步学习，不新增前置阶段。

## 面试可以诚实解释的取舍

- 为什么先建立指标合同：语言流畅不能保证分母、时间和单位正确。
- 为什么用固定 Python 工具：让重要数值可测试、可复算；首版没有任意代码执行。
- 为什么 SQL 还要与可信结果对照：执行成功不代表业务语义正确。
- 为什么限制两次下钻：限制时间和费用，避免没有证据的无限探索。
- 为什么离线演示不能证明模型能力：测试的是固定响应下的工程路径，模型泛化需要独立真实评测。
- 为什么报告不写“根因已找到”：分组变化与贡献仍属于观察性描述。
