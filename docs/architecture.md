# 架构、接口与失败行为

## 执行链路

Streamlit → FastAPI → 单线程后台队列 → LangGraph → 指标/SQL工具 → 隔离查询进程 → Python分析 → 报告。

状态图：理解任务 →（必要时等待澄清）→ 整体查询 → 比较 → 下钻决策 → 分组查询 → 比较；最多两个不同维度，然后生成报告。无有效分母时停止并保留证据。

当前是单实例、本机、单用户程序。SQLite 储存任务状态，刷新页面依靠 URL 中的任务编号恢复。服务重启把排队或运行任务标为中断，不承诺自动恢复执行。待澄清任务保留，提交答案时保留先前尝试并继承已用预算。

## 指标与查询

输入问题先转换为 AnalysisTask（指标、日期、比较、目标）。QueryResult 记录 SQL、结果列、完整结果、数据版本和耗时。EvidenceItem 记录程序计算的事实、单位和源查询。BusinessReport 只渲染已登记的证据编号。

Agent SQL 只读 daily_metrics / daily_segment_metrics；不会把 user_daily 暴露给模型。正向 AST 白名单拒绝尚未支持的结构；现版支持 SELECT、非递归 CTE、过滤、排序和 DATE 转换。未知函数、写入、连接和外部表函数均拒绝。

安全语法通过后，查询结果还必须与可信指标 SQL 的行集合、列和数值一致。它避免“能执行但分母或日期错了”被当作正确结果。对账不是简单比较 SQL 字符串。

查询子进程关闭 DuckDB 外部访问和扩展自动加载、锁定设置、限制内存和线程；父进程超时终止它。子进程不接收 API 密钥。没有操作系统级多租户沙箱，因此服务必须保持本机监听。

### 表粒度与使用规则

先明确输入表的一行代表什么，再决定是否聚合。已经聚合过的表仍可以向更粗粒度汇总；是否正确取决于目标粒度、指标可加性和分母。

| 表 | 一行的含义／预期唯一键 | 来源与使用规则 |
|---|---|---|
| `user_daily` | 一个用户的一个完整日期；`user_id, activity_date` | 用户维表 × 完整日期，关联分别聚合到用户日的观看、送礼数据。包含零行为行；不是活跃用户清单。仅供数据准备和人工复算，不暴露给模型。 |
| `daily_metrics` | 一天；`activity_date` | 从 `user_daily` 汇总。多日覆盖率应先分别加总分子、分母再相除；日均观看人数应除以完整日数。 |
| `daily_segment_metrics` | 某天、某维度、某分组；`activity_date, dimension, segment_value` | 从 `user_daily` 分别按年龄、性别汇总。每次只选一个维度；两套分组各自覆盖整体，不能合并加总，否则重复计算。 |

上述键是程序校验的逻辑唯一键，建表时没有声明数据库 PRIMARY KEY 约束。

| 字段／类型 | 含义与所在表 |
|---|---|
| `user_id`（保留源用户维表类型） | `user_daily` 的用户标识，不发送给模型。 |
| `activity_date`（DATE） | 三张表均有，北京时间的自然日。 |
| `age, gender`（VARCHAR） | `user_daily` 中的原始画像分组码；NULL 转为 `unknown`，不推断编码含义。 |
| `watch_count, gift_count`（BIGINT） | `user_daily` 中当日事件数，未匹配事件填 0。 |
| `gift_value`（DOUBLE） | 三张表均有，原始礼物价值总和；用户日无送礼记录填 0，源礼物值缺失或负值则拒绝导入。 |
| `watch_users, watch_gift_users, all_gift_users, unmatched_gift_users`（BIGINT） | 两张每日指标表中的观看、观看且送礼、全部送礼、无同日观看匹配的送礼用户数。 |
| `unmatched_gift_value`（DOUBLE） | 两张每日指标表中无同日观看匹配的礼物价值。 |
| `dimension, segment_value`（VARCHAR） | 分组表专有；维度限 `age`／`gender`，分组值保留原码或 `unknown`。 |

真实来源为项目二的 `user.parquet`、`click.parquet`、`gift.parquet`；合成来源由固定种子生成。源时间戳为 Unix 毫秒。导入事件范围为北京时间 `[2025-05-05 00:00, 2025-05-18 00:00)`；面向用户的 DATE 起止日期均包含。指标定义集中在 `semantic.py`。

`dataset_metadata` 保存来源及校验摘要、时区、日期范围、完整日期、指标版本、数据版本、三张表的行数和生成时间。表合同使用本节集中说明；当前不实现动态元数据平台或跨任务 Memory。新增校验结果只在下一次成功导入时写入元数据，旧库不会自动补写或被视为完成新校验。

### 基础数据校验与失败处理

| 检查 | 执行规则与失败行为 |
|---|---|
| 关键 NULL | 用户维表键必须非空且唯一。日期筛选前统计观看、送礼源中的 NULL 时间戳；无法确定其所属窗口，出现任意一条即拒绝导入并报告两类数量。只统计缺失数量，不分析范围外行为。窗口内事件必须匹配用户维表，礼物值必须非空且非负。 |
| 行数与表粒度 | 用户日行数 = 用户维表人数 × 完整日数；每日指标行数 = 完整日数；分组表行数 =（年龄组数 + 性别组数）× 完整日数，组数按 NULL 转 `unknown` 后计算。三张表的逻辑键均检查 NULL 和重复。检查记录在 `checks.table_shapes`。 |
| JOIN 膨胀 | 观看、送礼先各自按用户日聚合，再关联到用户 × 日期底表。关联后保持底表粒度，并核对观看事件总数、礼物总值；两个维度各自汇总回整体。模型 SQL 禁止 JOIN，不增加通用 JOIN Agent。 |
| 日期与可用性 | 事件先按允许范围筛选再聚合；请求日期必须在已标记完整日期内，比较窗口等长且不重叠。完整日标记不是自动日志完整性探测，不能保证原始采集没有遗漏。 |
| SQL 结果 | 与可信查询比较完整行集合、列和数值，拒绝丢行、截断、错误窗口或错误维度；无有效分母时停止分析。 |

导入全部在临时数据库执行，检查失败即删除临时文件并保留原有效库；成功后才替换。成功元数据记录 `checks.timestamp_nulls`（两类均为 0）；失败时通过错误信息报告缺失数量，不给旧库写入新“通过”记录。查询失败按现有修复预算处理，不把未验证结果用于报告。

当前只分析开发期行为，保留项目二测试期保护。未来接入 ML 时再检查特征的可获得时间早于预测时点、未来标签窗口与特征分离，并遵守训练／验证／测试边界；这部分仍属于扩展路线。

## API

| 方法与地址 | 输入/输出 |
|---|---|
| GET /health | 配置是否存在（不显示凭证）与本机范围 |
| GET /v1/datasets | 已准备数据集、可用完整日期与版本 |
| GET /v1/metrics | 指标名称、单位、定义 |
| POST /v1/analyses | question、dataset_id、mode，可选 metric/current/baseline/trend_only；返回 202 与 run_id |
| GET /v1/analyses/{id} | 状态、任务、执行记录、错误或报告 |
| POST /v1/analyses/{id}/clarifications | 确认 metric、current、baseline 或 trend_only |
| GET /v1/analyses/{id}/artifacts/{name} | 只下载登记在此任务下的文件 |

current/baseline 使用 `{"start":"2025-05-12","end":"2025-05-17"}`，两个端点均包含。内部事件过滤使用北京时间左闭右开边界。

提交样例：

```json
{"question":"最近六天礼物总价值为什么变化？","dataset_id":"synthetic","mode":"demo"}
```

状态：queued、running、needs_clarification、completed、insufficient_evidence、failed。

无密钥的 live 请求与未准备的数据集返回 409；不存在的任务／文件返回 404；类型不合法返回 422。其他运行失败通过任务状态表达。

## 报告与可观察性

模型只选择证据高亮和受控解释／建议代码，不直接撰写数字。量化结论由 Python 模板渲染，图表来自同一查询结果。当前受控叙述会牺牲一些语言灵活性，以保证证据绑定。

记录阶段、查询、修复、维度选择、调用次数、耗时、token 用量和版本；不记录 API 凭证或模型隐藏思考内容。固定响应模式的真实模型调用数为零。

失败也保存 evidence.json；未完成报告不标记成功，下载入口不暴露未登记的路径。
